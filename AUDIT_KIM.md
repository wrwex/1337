# Отчет об исправлениях алгоритма по ВМ

Дата 9 октября 2026 года. Основание — КИМ 09.02.06-3-2027 Том 1 Задание 1, предоставленный пользователем.

## Результат

Подготовлена новая последовательность для ISP, HQ-SW, HQ-RTR, BR-RTR, BR-FW, HQ-SRV, BR-SRV и HQ-CLI. Платформы уточнены пользователем: ALT Linux, EcoRouter 3.2.6.2 и Ideco 21.7.130. Все команды и настройки находятся в [актуальном алгоритме](https://github.com/wrwex/1337/blob/main/README.md). Это исправление инструкции; выполнения этих команд на ВМ не было.

Исходная редакция репозитория: dc1507c6ce02c0ed6f497b255d8a45722ab11c6f. Рассмотрены README.md и CHECKIN.docx, включая встроенные изображения. Первоначальный DOCX сохраняется как историческая версия с явной отметкой legacy.

## Исправления по каждой ВМ

### ISP

Добавлены адреса 172.16.1.1/28 и 172.16.2.1/28, получение адреса WAN и default route по DHCP, постоянное IPv4 forwarding. Добавлены правила транзита между WAN-адресами роутеров, включая GRE. MASQUERADE ограничен WAN к провайдеру; между офисными WAN-интерфейсами NAT не нужен. Повторное добавление снимков iptables через >> заменено записью актуального снимка через >. Команда часового пояса Linux использует Europe/Moscow для московской площадки.

### HQ-SW

В исходном материале отсутствовала коммутация. Добавлен VLAN-aware bridge с trunk VLAN100/200/999 к одному порту HQ-RTR и access-портами к HQ-SRV/HQ-CLI. Адрес управления 10.10.30.2/29 назначен интерфейсу VLAN999. Настройка сохраняется через systemd-службу, описаны проверка VLAN, ограничения для старого моста и повторный запуск после ручного перезапуска сети.

### HQ-RTR

Добавлены L3-интерфейсы и их привязка к физическим портам через service-instance. Все HQ VLAN используют один физический ge1. Создана локальная учетная запись net_admin с паролем КИМ и ролью admin. NAT-пул VLAN200 согласован с /28. Ключ OSPF исправлен с P@ssword на P@ssw0rd. DHCP-сервер выдает HQ-CLI адрес 10.10.200.3/28, шлюз 10.10.200.1, DNS 10.10.100.2 и домен au-team.irpo. Шлюз исключен из пула. Окончательный DNS роутера — HQ-SRV.

### BR-RTR

Адрес 10.10.20.2/30 в исходном GRE не относился к требуемой сети и не совпадал с туннельной подсетью HQ. В новом основном варианте GRE офисов использует 10.10.10.0/31: HQ .0, BR .1. Добавлен отдельный физический транзит к BR-FW и дополнительный GRE BR-RTR–BR-FW. Локальная сеть BR-SRV находится за BR-FW, а не прямо на BR-RTR. Добавлены net_admin, OSPF MD5 и PAT для сети сервера/самого BR-FW; отмечены inside на физическом и дополнительном туннельном интерфейсах. Синтаксис для другого поколения NAT явно отделен от исходного варианта.

### BR-FW

Отсутствовавшее устройство полностью включено в инструкцию. Для Ideco предусмотрены штатные настройки веб-интерфейса: локальные Ethernet FW-NET и BR-NET, маршрут по умолчанию к BR-RTR, GRE и OSPF, MD5, Redistribute connected, фильтрация анонсов, межсетевые правила, имя, часовой пояс и DNS HQ-SRV. Отключено объявление default route в OSPF. Не предлагается писать произвольные конфиги FRR или etcnet в Ideco: они не заменяют ее постоянную управляемую конфигурацию.

### HQ-SRV

Добавлены создание sshuser с UID2027 и пароль КИМ. Символ » в исходной команде не является перенаправлением Bash; используется отдельный файл sudoers.d и проверка visudo. SSH изменен с порта 2026 на 2027, сохранены AllowUsers sshuser, MaxAuthTries2 и баннер. Добавлены проверка sshd и реальные тесты входа/отказа.

В DNS убраны закомментированные forwarders и неоднозначное копирование снимков. Добавлены SOA/NS реального HQ-SRV, A-запись BR-FW, PTR для BR-SRV, правильные in-addr пути и проверки BIND. Задан доступ к рекурсии для офисных сетей, а не произвольного внешнего Интернета. Создание rndc с обрезанием вывода исключено как ненужное для задания. Для ALT объяснены штатные include/directory/chroot, чтобы не создать проверяемый файл, который реальный демон не использует.

### BR-SRV

Адрес сервера 10.20.20.2/28 и шлюз 10.20.20.1 сохранены, но теперь шлюз однозначно принадлежит BR-FW. Добавлены sshuser UID2027, пароль, sudo и SSH2027. После установки пакетов временный публичный DNS заменяется HQ-SRV. Проверяется разрешение имен, PTR и SSH через сеть другого офиса.

### HQ-CLI

DHCP на клиенте был показан, но не было сервера. Новая инструкция согласует клиента с DHCP HQ-RTR и A hq-cli. Предусмотрены взаимоисключающие варианты NetworkManager и etcnet; внешний DNS не прописывается поверх параметров аренды. Используется динамический пул из одного адреса для единственного клиента, предусмотренного заданием. При расширении пула нужен DHCP reservation или обновление DNS.

## Существенные условия применения

1. **Подсети /31.** Основной вариант экономит адреса в соответствии с RFC3021. Для конкретных сборок нужны проверка принятия маски, ping и соседство. В руководстве есть полный вариант /30; он используется при несовместимости или согласовании экспертов.
2. **OSPF.** Буквальные требования КИМ к BR-RTR и BR-FW конфликтуют при обычном соседстве на Ethernet. Предложен второй GRE, поддерживаемый документацией Ideco21, чтобы оставить активный OSPF на роутерах только на туннелях. Это интерпретация, требующая согласования с экспертами. Альтернатива — разрешенное ими Ethernet-соседство; инструкции вариантов разделены.
3. **Интерфейсы и версии.** Версии платформ сообщены пользователем, но их CLI/карты не обследованы. Имена ens3/ens4/ens5 и ge0/ge1 — схема для подстановки после инвентаризации. Для зависимых от версии команд даны проверки CLI; они не объявляются исполненными.
4. **Часовой пояс.** В примере Москва; на другой площадке выбрать ее зону. HQ-SW исключен из обязательного требования, но может иметь правильное время.
5. **Оценивание.** Приложения 1–4 не предоставлены, баллы и окончательная экспертная трактовка не рассчитываются.
